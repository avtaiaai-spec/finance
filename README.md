# Мои финансы

Локальное приложение для личного учёта на React, TypeScript и Vite. Русский интерфейс, рубли и копейки, адаптивная вёрстка, светлая/тёмная/системная темы. Финансовые данные не передаются на сервер; шрифты поставляются вместе с приложением.

## Запуск

Требуется Node.js 22+ (проверено на 24.19.0) и npm.

```sh
cd /workspace/finance
npm ci
npm run dev -- --port 5173
```

Для production: `npm run build`, затем разместить содержимое `dist/` на статическом HTTPS-хостинге. Проверка production-сборки: `npm run preview -- --port 4173`.

## Возможности

- Доходы и расходы: добавление, редактирование, подтверждение удаления, категории, комментарии и произвольные даты.
- История с поиском, фильтрами, сортировкой, календарными и произвольными периодами; кнопка «Вся история».
- 28 готовых категорий, собственные иконки и цвета, порядок, архивирование и восстановление. Категории с операциями или лимитами защищены от удаления и смены типа.
- Календарные недельные, месячные, квартальные и годовые лимиты; остаток, перерасход, предупреждения с 80%, отключение.
- Доходные, расходные и накопительные цели. Пополнения накоплений фиксируются отдельно и могут быть исправлены или удалены. Расходная цель достигается только после окончания периода, если лимит соблюдён.
- Интерактивные диаграммы, сравнение периодов, структура расходов, контроль лимитов.
- Резервные копии JSON, проверка импортируемых данных и подтверждение полной замены, CSV с BOM и разделителем `;` для Excel.
- Отдельный деморежим не изменяет личные данные. Первое открытие содержит только категории, без операций.
- Manifest и PNG-иконки для установки на главный экран. Полноценная офлайн-работа не реализована. Для iPhone: Safari → Поделиться → На экран Домой, после размещения на HTTPS-сайте.

## Хранение

`localStorage`, ключ `calm-finance-v1`, версия структуры 1. Суммы — целые копейки. Даты — локальные строки `YYYY-MM-DD`. Неделя начинается в понедельник, кварталы календарные. Лимиты разных периодов не суммируются. Результат периода — разница доходов и расходов, а не банковский баланс. Кредиты и возвраты — обычные категории, без модели задолженности.

Данные привязаны к браузеру и адресу сайта, не синхронизируются между телефоном и компьютером. Регулярно скачивайте резервные копии. При ошибке чтения сохранённая запись не перезаписывается: её можно скачать в настройках. Изменения принимаются только после успешного сохранения в браузере.

```sh
npm test

```

`npm test` проверяет финансовую модель. Сквозной тест проверяет операции, категории, лимиты всех периодов, накопления, графики, темы, экспорт/импорт, изоляцию демо и отсутствие горизонтального скролла на ширинах 320/375/390 px. ## Публикация на GitHub Pages

Адрес проекта: https://avtaiaai-spec.github.io/finance/ . В Vite задан базовый путь `/finance/`; manifest и иконки используют соответствующие относительные пути.

В GitHub откройте Settings → Pages → Build and deployment → Source → **GitHub Actions**. После отправки изменений в main workflow `.github/workflows/pages.yml` устанавливает зависимости, запускает тесты, собирает и публикует `dist/`. Статус виден во вкладке Actions. После успешного Deploy откройте сайт в Safari → Поделиться → На экран Домой. Это публикация сайта, отдельная от публикации облачной среды Codex.

## Импорт из CoinBox

В приложении: **Настройки → Импорт из CoinBox CSV**. На телефоне настройки доступны через меню в правом верхнем углу. Выберите выгрузку с колонками `Date,Type,Category,Amount,Currency,Note`, проверьте предпросмотр и нажмите «Добавить операции».

Поддерживаются UTF-8 (в том числе BOM), CSV с запятыми или точкой с запятой, кавычки и многострочные комментарии. Валюта — только RUB; суммы положительные, максимум две цифры после запятой. Даты — `YYYY-MM-DD`, при необходимости с `HH:mm` или `HH:mm:ss`. Неподдерживаемые типы, валюты и ошибочные записи блокируют импорт целиком, текущие данные не изменяются.

Импорт **добавляет**, а не заменяет операции; существующие лимиты, цели и настройки сохраняются. Категории сопоставляются по типу и названию без учёта регистра и лишних пробелов; неизвестные создаются отдельно, без автоматического объединения похожих названий. Повторная или пересекающаяся выгрузка распознаётся по исходным значениям строки с учётом времени и количества одинаковых строк. Две полностью одинаковые операции в исходном файле сохраняются как две операции. Ручные записи не исключаются автоматически. Метки импорта сохраняются при редактировании и в JSON-копии. Если повторная выгрузка содержит изменённые исходные записи, они считаются новыми; импорт не обновляет и не удаляет старые записи автоматически.

Файл обрабатывается только в браузере. Не добавляйте личные CSV-выгрузки в репозиторий.

Дополнительная сквозная проверка: `python tests/browser_coinbox.py` (по умолчанию синтетические данные; адрес задаётся `APP_URL`). Для локальной проверки своей выгрузки можно передать `COINBOX_FIXTURE=/путь/к/файлу.csv`; файл должен находиться вне репозитория.

## Остаток денег

На главной автоматически показана сумма **начальные деньги + все внесённые доходы − все расходы за всю историю по сегодня**, включая импорт из CoinBox. Начальные деньги по умолчанию равны нулю; их можно указать через карандаш на карточке или в настройках. Это сумма, которая была до самой первой операции; она не является доходом и не попадает в статистику доходов. Сумма сохраняется в JSON-копии, но отсутствует в CSV CoinBox. Ручной ввод остатка не требуется. Пустая история показывает 0 ₽; отрицательное значение не скрывается. Переключение месяца, недели или года меняет только статистику ниже, а не общий остаток. Будущие операции включаются в остаток, когда наступает их дата. Правки, удаление и импорт операций сразу пересчитывают сумму.

Прежние ручные настройки остатка могут оставаться в старой JSON-копии, но больше не участвуют в расчёте. Для точности необходимо внести всю историю доходов и расходов. Проверка интерфейса: `APP_URL=http://127.0.0.1:4175/finance/ python tests/browser_balance.py`.

Прямая ссылка вида `#starting-money=1000` открывает форму начальной суммы с заполненными 1 000 ₽. Она ничего не меняет автоматически: требуется нажатие «Сохранить и пересчитать». Повторное сохранение заменяет начальную сумму, а не прибавляет её снова. Сквозная проверка: `python tests/browser_starting.py`.

## Цветовые темы

В настройках отдельно выбираются режим (светлый, тёмный или системный) и палитра: зелёная, розовая, жёлтая, бордовая или коричневая. У каждой палитры свои цвета фона, карточек, текста, кнопок и форм для светлого и тёмного режима. Системный режим реагирует на изменение настроек устройства, сохраняя выбранный цвет. Выбор сохраняется локально и в JSON-копии; старые копии без палитры открываются с зелёной темой. Цвета категорий и значения финансовых показателей не меняются при выборе оформления.

Проверка всех 15 сочетаний, переключения системного режима, сохранения и мобильной вёрстки: `python tests/browser_themes.py` при запущенной production-сборке (адрес задаётся через `APP_URL`).
